# LifeOS Examples

**English** | [简体中文](./README.zh-CN.md)

These examples validate whether LifeOS v0.1 can move from a real situation to action and learning rather than remaining conceptual.

## Example 1: Should I Change Jobs?

### Situation
The current job is stable but growth has slowed. An external opportunity offers higher income but greater risk.

### Runtime
```text
Clarify → Self → Context → Goal → Thinking → Decision → Next Action
```

### Facts / Assumptions / Unknowns
- Fact: the current role is stable.
- Fact: the external role pays more.
- Assumption: the new role will necessarily accelerate growth.
- Unknown: future manager quality and long-term business stability.

### Decision Focus
Do not reduce the problem to salary comparison. Clarify what the current life stage is actually optimizing: stability, growth, income, family time, or long-term career capital.

### Next Action
Before making the final choice, verify the highest-value unknown—for example, ask the future manager about team goals, success criteria, and 12-month business risks.

### Checkpoint
Re-run the Decision System after critical unknowns are reduced.

## Example 2: Suddenly Taking Over an Unfamiliar Project

### Situation
The previous owner leaves and you must rapidly take over a risky project in an unfamiliar domain.

### Runtime
```text
Role → Context → Thinking → Learning → Communication → Execution
```

### First Questions
1. What is the actual project outcome and success criterion?
2. How far is current reality from the plan?
3. What are the top three risks?
4. Who holds critical information?
5. Which decisions are uniquely mine to make?

### Next Action
Create a one-page Project Situation Map before rebuilding the full plan: Outcome, Milestones, Stakeholders, Current State, Top Risks, Unknowns, Next Checkpoint.

## Example 3: An Important Project Failed

### Situation
The project slipped and ultimately underperformed. Team morale is low.

### Runtime
```text
Emotion & Energy → Review → Thinking → Learning → Execution
```

### Review
```text
Expected: launch on schedule and achieve target metrics
Actual: delayed launch and below-target result
Gap: both schedule and outcome missed
```

Then distinguish:
- Decision Quality: were choices reasonable based on information available at the time?
- Execution Quality: which problems were controllable during delivery?
- Luck / External: which outcomes came from external changes?

### Lesson Rule
Avoid conclusions such as “communicate better next time.” Create observable behavior change instead, for example:

> For every high-risk dependency, confirm owner, deadline, fallback, and checkpoint before implementation begins.

### Next Action
Add the rule to the future project playbook and verify it at the first checkpoint of the next project.

## Validation Standard

```text
Real Problem
   ↓
Structured Understanding
   ↓
Appropriate Core OS Routing
   ↓
Concrete Next Action
   ↓
Real Result
   ↓

```
