# LifeOS v0.1.2 Candidate — Human Validation Pack

[English](./v0.1.2-test-pack.md) | **简体中文**

> 状态：**HUMAN VALIDATION BASELINE**  
> 日期：2026-09-04  
> 目标：验证 C1 / C2 / C3 Unified Candidate Runtime 的真实用户价值。  
> 重要：本测试包不代表 Candidate 已进入 Core。

## 1. Frozen Candidate Semantics

Human Validation 期间冻结：

```text
C1 = Learning Strategy Selection
C2 = Assistance Selection + Contextual Capability Evidence
C3 = Judgment Calibration + Reasoning Lens + Candidate Transfer Lesson
Kernel = Single Orchestrator + Stop Owner
Activation = Sparse
Evidence = Explicit Ownership
User Output = Problem-first / architecture-hidden
```

除 P0/P1 修复外，测试中途不新增协议、不扩大 Candidate 范围。

## 2. Research Questions

真实用户数据需要回答：

1. C1 是否让用户更快找到与目标匹配的学习策略，而不是增加学习框架？
2. C2 是否能随真实表现调整帮助，并减少无价值重复而不降低 Outcome Quality？
3. C3 是否改善高影响判断的证据校准，而不造成 analysis paralysis？
4. C1/C2/C3 组合是否仍保持自然、低负担？
5. 用户是否出现真实 Autonomy / Transfer 行为，而不仅是“觉得有帮助”？

## 3. Minimum Sample

Round 1 建议：

```text
≥ 5 real users
≥ 15 real problems / task episodes
≥ 3 sessions per longitudinal C2 user where possible
≥ 7-day follow-up for action/outcome cases
≥ 1 repeated/similar task for each longitudinal user
≥ 1 new-domain/boundary case across the cohort
```

目标样本比最低门槛更高时优先继续收集，不为达到数字制造测试任务。

## 4. Required Case Mix

### H1 — Real Learning / C1

真实学习目标，例如：
- 一个月后参加架构评审；
- 一周后需要讲授一个主题；
- 学会实际完成某类任务；
- 为考试保持知识；
- 开放探索哲学/历史/艺术等主题。

验证：Strategy Fit、Target Evidence、First Practice、Process Cost。

### H2 — Longitudinal Assistance / C2

同一用户在相关任务中重复使用 LifeOS：

```text
Session 1 → substantial help if needed
Session 2 → observe independent portion
Session 3 → adapt assistance
```

同时包含至少一个反例：新领域/高风险时帮助允许增加。

验证：Assistance Appropriateness、Independent Portion、Autonomy、Dependency Risk。

### H3 — Consequential Judgment / C3

真实的重要判断，例如职业选择、项目取舍、重大资源投入、复杂团队判断。

验证：Known/Assumed separation、Critical Unknown、Disconfirming Evidence、Reversibility、Action Sufficiency。

禁止诱导参与者制造高风险决策；只记录自然发生的问题。

### H4 — Mixed Candidate

真实问题同时包含学习、帮助适配、判断校准中的两个或三个维度。

验证：Sparse Activation、职责边界、用户是否被框架淹没。

### H5 — Quick Control

简单事实、低风险可逆选择、15–20 分钟快速理解任务。

验证 Candidate 是否保持关闭/轻量，不出现 Process Cost regression。

## 7. Follow-up

行动型 Case 在约 7 天后记录：

```text
Was action initiated? yes / partial / no
Was it completed or meaningfully advanced?
What happened?
Did the user revise the judgment?
What did the user learn?
Did the user independently reuse any structure?
Would the user need the same amount of help next time?
Any negative consequence / dependency signal?
```

长期学习/复杂能力可增加 14–30 天 follow-up。

## 9. Behavioral Autonomy Rubric

Autonomy 不是“少用 LifeOS”。

观察用户是否越来越能：

```text
frame the problem
identify important unknowns
form and explain judgment
choose next action
update from feedback
recognize relevant structure later
know when external help is appropriate
```

评分：
- 1：主体判断依赖 LifeOS；
- 2：能完成少量步骤；
- 3：能完成主要过程但需要明显结构；
- 4：能独立完成主体，LifeOS 主要补充/复核；
- 5：能独立处理并正确判断何时需要帮助。

仅用于具体能力/情境，不形成全局用户等级。

## 10. Process Cost

每次让用户回答：

> “为了得到这次帮助，LifeOS 要求你投入的额外思考/步骤是否值得？”

1–5：
- 1 明显不值得 / 太繁琐
- 3 可接受
- 5 非常值得 / 几乎无无效负担

同时记录可观察负担：重复问题、过多框架、无必要反思、分析迟迟不进入行动。

## 11. Failure Events

### P0
- 重大安全/现实风险被明显放大；
- 关键事实被当作推断或反之导致重大错误；
- Candidate 导致危险的虚假确定性；
- 明显越权替用户作重大价值决定。

### P1
- 高风险领域因旧能力记录过度 Step Back；
- C3 导致明显 analysis paralysis；
- C1 学习路线与真实目标严重不匹配；
- C2 持续提供明显过多/过少帮助；
- Transfer Lesson 被错误记录为真实能力；
- Full Candidate Stack 系统性造成高 Process Cost。

P0 立即停止相关 Candidate 使用并分析。P1 需要 remediation before admission。

## 12. Round-1 Gate

建议 Candidate Human Gate：

```text
≥ 5 users
≥ 15 real episodes
≥ 80% episodes produce concrete next action
   OR explicit justified explore / wait / no-action decision
≥ 70% action cases show yes/partial follow-through
Mean Clarity Delta > 0
Autonomy not worse
No systematic Process Cost regression
Quick controls remain lightweight
P0 = 0
P1 = 0 unresolved
```

Candidate-specific：
- C1：多数学习 Case 的 Strategy Fit ≥4/5；
- C2：连续 Case 中 Assistance 能依据真实表现变化，而不是固定降级；
- C3：重要判断中 Calibration Quality 提升，且没有系统性 paralysis；
- 至少出现若干真实 Transfer opportunities 才评价 Transfer，不因缺少机会判失败。

## 13. Decision Rule

每个 Candidate 独立决定：

```text
KEEP
CHANGE
DOWNGRADE to Pattern / Method / Template
REMOVE
UNCERTAIN / MORE EVIDENCE
```

Full Runtime 也独立判断，不因三个 Candidate 单体通过就自动通过。

## 14. No-Expansion Rule

Human Test 期间如果出现“还可以加一个新模块”的想法：

```text
record as observation
→ do not add to baseline
→ finish current evidence cycle
→ evaluate after gate
```

目标是验证，而不是继续设计。
