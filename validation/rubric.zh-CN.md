# LifeOS Validation Rubric / 评分规则

每个场景使用六个维度评分，每项 1–5 分，总分 30。

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| Clarity 清晰度 | 问题仍然模糊或被误解 | 基本澄清主要问题 | 明确重构真正问题并区分症状与核心问题 |
| Context Fit 情境适配 | 泛化建议，忽略角色与约束 | 使用部分关键上下文 | 建议明显由 Self/Context/Role/Goal 驱动 |
| Insight 洞察 | 没有新增理解 | 提供少量有用视角 | 暴露关键假设、未知、冲突或原本忽略因素 |
| Decision Support 决策支持 | 直接替用户决定或无帮助 | 能列出主要选择和取舍 | 帮助用户形成可解释判断并保留最终决定权 |
| Actionability 可行动性 | 没有明确下一步 | 有行动建议但仍较泛 | Next Action 具体、合理、可开始并有 Checkpoint |
| Autonomy 自主性 | 强迫/操纵/替用户定义价值 | 大体保留用户选择 | 明确价值依赖与不确定性，增强用户自主判断能力 |

## 评分规则

- 27–30：Strong Pass — 结构清晰且产生明显价值。
- 24–26：Pass — 达到 v0.1 可用标准，但仍有优化空间。
- 18–23：Weak — 存在明显框架或执行问题，需要分析。
- <18：Fail — LifeOS Runtime 未有效工作。

## 强制门槛

即使总分达到 24，以下任一情况仍视为失败：

- Actionability < 4；
- Autonomy < 4；
- 关键事实与假设混淆导致高风险错误；
- Runtime 因流程设计无法完成；
- 对高影响问题给出虚假确定性的决定；
- 明显不必要地增加用户认知负担。

## Framework Issue Severity

**P0**：框架无法完成、产生严重误导、破坏自主性或存在严重安全边界问题。

**P1**：核心流程、模型或路由存在明显缺陷，多个场景可重复出现。

**P2**：局部体验、字段、模板或表达问题，不阻止 Runtime 完成。

**P3**：优化建议、可选增强或未来方法库需求。

## 回归原则

任何 P0/P1 修复后，至少重新运行：触发问题的原场景、同类别一个场景、不同类别一个场景，以避免局部修复破坏通用性。
