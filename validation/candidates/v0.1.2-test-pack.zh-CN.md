# LifeOS v0.1.2 Candidate Validation Pack

[English](./v0.1.2-test-pack.md) | **简体中文**

> 目标：在不修改冻结 v0.1.1 基线的前提下，验证三个候选机制是否具有稳定增量价值。

## 1. Candidate Set

```text
C1 Learning Strategy Router
C2 Capability Growth + Assistance Ladder
C3 Cognitive Augmentation
   ├─ Cognitive Calibration
   ├─ Mental Model Router
   └─ Metacognitive Transfer
```

候选机制的默认结论不是“加入”。每个候选最终只能得到：

```text
KEEP    保留并进入下一版本候选
CHANGE  有价值，但需要修改
REMOVE  没有足够增量价值
DOWNGRADE 降级为 Pattern / Method / Template
UNCERTAIN 证据不足，继续验证
```

## 2. Test Principle

核心问题不是“这个设计听起来是否合理”，而是：

> **相比冻结的 LifeOS v0.1.1，它是否让真实输出或用户能力产生可观察的改善，并且没有付出不合理的 Process Cost？**

建议比较：

```text
A = Frozen LifeOS v0.1.1
B = v0.1.1 + one isolated candidate
```

优先逐项测试，不要一开始把三个 Candidate 全部叠加，否则无法判断增量来自哪里。

## 3. Metrics

沿用现有指标：

- Clarity
- Context Fit
- Insight
- Decision Support
- Actionability
- Autonomy
- Process Cost（越低越好）

增加候选机制专用指标：

### Strategy Fit
所选方法是否真正匹配用户目标、水平、时间和使用场景？

### Calibration Quality
是否正确区分事实/解释/假设/未知，并让置信度与证据更匹配？

### Transfer Value
用户是否获得可以用于下一次类似或新问题的能力/原则？

### Assistance Appropriateness
LifeOS 的帮助强度是否与用户当前能力、风险和情境匹配？

### Overhead Penalty
新增机制是否让简单问题变得不必要地复杂？

## 4. C1 — Learning Strategy Router

### L01 Quick Orientation
> 我只有 30 分钟，想先弄懂 AI Agent 是什么，不准备写代码。

期望：Quick；L0–L1；整体地图、核心概念、例子；避免长期课程计划。

### L02 Architecture Review
> 一个月后我要参加 AI Agent 架构评审。我会软件开发，但对 Agent 架构了解不系统，应该怎么学？

期望：目标至少 L3；Domain Map → Architecture Mechanisms → Tradeoffs → Cases → Review Practice。

### L03 Theory Without Practice
> 我已经看了很多机器学习课程和书，但还是不会独立做项目。我还应该继续看课吗？

期望：识别 Skill/Application Gap；减少输入，转向 Project/Deliberate Practice/Feedback。

### L04 Teach Tomorrow
> 明天下午我要给团队讲一个我刚接触的技术概念，目标是讲清楚并回答基础问题。

期望：Feynman/Teach-back/Q&A；时间约束驱动；不追求专业级掌握。

### L05 Exam Retention
> 我准备一个知识点很多的考试，学过但总是记不住。

期望：Retrieval + Spacing + Error Log + Mock Test；不能只推荐重读。

### L06 Professional Skill
> 我已经会基础编程，希望半年后能独立负责生产级后端系统。

期望：L4；真实项目、工程实践、反馈、故障/设计案例；有能力证据。

### L07 Open Exploration
> 我想长期学习哲学，没有考试，也没有明确截止日期。

期望：不要强行项目化；支持 Explore；建立地图、阅读/思考/写作/对话循环。

### C1 Pass Signals

- 不同学习目标产生实质不同策略；
- Strategy Fit 优于 v0.1.1；
- 更快进入 Practice；
- Verification 与目标深度匹配；
- Quick 场景 Process Cost 不恶化。

## 5. C2 — Capability Growth + Assistance Ladder

此候选必须用**连续场景**测试，而不是单轮回答。

### G01 Career Decision — Round 1
用户第一次处理两个工作机会，不熟悉系统决策。

期望：Guide/Collaborate，帮助建立 criteria / uncertainty / reversibility。

### G02 Career Decision — Round 2
数周后出现新的职业选择。输入中表明用户已经会主动列 criteria 和关键未知。

期望：减少重复教学，转向 Coach/Calibrate。

### G03 Career Decision — Round 3
用户自己给出完整分析，只要求检查是否遗漏。

期望：A4 Calibrate；不要重新替用户做一遍。

### G04 New Domain Reset
同一用户进入完全陌生且高风险的新领域。

期望：允许 Assistance 临时上升；证明 Ladder 不是线性等级制度。

### G05 Transfer
用户把之前项目复盘中学到的“责任-权限差距”主动用于新的组织问题。

期望：识别 Transfer Evidence，而不是重新教学。

### C2 Pass Signals

- 相似问题中 Assistance 随能力证据合理下降；
- 新领域/高风险时可以合理上升；
- Autonomy 提升而结果质量不下降；
- 不把 Assistance Level 当人格或能力标签；
- 能识别真实 Transfer，而不是仅记录“用户满意”。

## 6. C3 — Cognitive Augmentation

### C01 Self Attribution
> 这个项目失败了，我觉得这证明我根本不适合做负责人。

测试：Fact vs Interpretation；Self Evidence Gate；alternative explanations；避免廉价安慰。

### C02 Sunk Cost
> 项目已经投入一年和很多钱，现在停掉太可惜，所以我倾向继续。

测试：Sunk Cost / Opportunity Cost 是否真正改变决策结构；不只是报模型名字。

### C03 Two Good Options
> 两个工作机会都很好，我一直想找到“正确答案”，但信息不完整。

测试：Uncertainty / Reversibility / Option Value；明确什么信息值得继续收集。

### C04 Local Optimization
> 团队不断加人，但交付越来越慢。是不是应该继续招更多人？

测试：Systems / Bottleneck / Feedback；寻找替代解释。

### C05 Conflict Interpretation
> 领导反对我的技术方案，我觉得他就是不懂技术。

测试：事实与归因分离；alternative hypotheses；不自动站队。

### C06 High-confidence Consequential Choice
> 我对这个重大选择有 90% 把握，身边人也支持。我准备一次性投入大量资源。

测试：disconfirming evidence、downside、reversibility；不因为用户自信就提高 AI 确信度。

### C07 Simple Reversible Choice
> 今天午饭吃 A 还是 B？两个都可以。

测试：Stop Rule；不启动完整 Calibration/Model 流程。

### C08 Repeat Case
在用户已经掌握 Fact/Interpretation/Assumption 分离后再次提供类似判断问题。

测试：从 Guide 转为 Calibrate；避免重复教育。

### C3 Pass Signals

- 减少事实/解释/假设混淆；
- 更容易发现关键反证与替代解释；
- Mental Model 有实际决策增量；
- 不出现“模型炫技”；
- 简单问题不会被过度分析；
- 重复场景出现可观察的 Metacognitive Transfer。

## 7. Interaction Tests

单项通过后，再测试组合是否产生协同或冲突。

### I01 Learn to Judge
> 一个月后要参与陌生技术领域的架构评审。

测试 C1 + C3：学习策略是否不仅帮助“知道”，还帮助形成判断与校准能力。

### I02 Learn, Apply, Transfer
> 用户学习项目风险管理 → 实际管理一个项目 → 复盘 → 新项目。

测试 C1 + C2：学习能力是否能迁移并降低后续 Assistance。

### I03 Cognitive Growth
> 同类重要决策连续出现三次。

测试 C2 + C3：Calibration 能力是否被用户逐渐内化。

## 8. Experimental Order

```text
Phase 1  Candidate Isolation
         v0.1.1 vs v0.1.1+C1
         v0.1.1 vs v0.1.1+C2
         v0.1.1 vs v0.1.1+C3

Phase 2  Failure Analysis
         KEEP / CHANGE / REMOVE / DOWNGRADE

Phase 3  Interaction Tests
         only retained candidates

Phase 4  Human Real-world Validation
         real learning / decisions / follow-through / transfer

Phase 5  v0.1.2 Decision
```

## 9. Candidate Gate

一个 Candidate 进入 v0.1.2 至少应满足：

1. 在目标场景中有重复可见的增量；
2. 至少改善一个主要目标指标，且没有明显损害其他核心指标；
3. Autonomy 不下降；
4. Process Cost / Overhead 可接受；
5. 没有 P0；
6. 新 P1 有明确修复方案；
7. 不能被更简单的现有机制完全替代；
8. 对 Human Capability 的主张有行为证据，而不仅是文本评分。

## 11. Version Discipline

```text
Frozen v0.1.1
     ↓
Candidate Experiments
     ↓
Evidence
     ↓
KEEP / CHANGE / REMOVE / DOWNGRADE
     ↓
v0.1.2 Candidate Build
     ↓
Regression
     ↓
Blind + Human Validation
```

> **LifeOS 的方法论不是通过“听起来正确”进入 Core，而是通过证据获得位置。**
