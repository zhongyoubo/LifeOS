# LifeOS v0.1.2 Candidate Validation Pack

**English** | [简体中文](./v0.1.2-test-pack.zh-CN.md)

> Purpose: validate three candidate mechanisms for stable incremental value without modifying the frozen v0.1.1 baseline.

## Candidate Set

```text
C1 Learning Strategy Router
C2 Capability Growth + Assistance Ladder
C3 Cognitive Augmentation
   ├─ Cognitive Calibration
   ├─ Mental Model Router
   └─ Metacognitive Transfer
```

Each candidate starts as UNCERTAIN and may become KEEP, CHANGE, REMOVE, DOWNGRADE (to Pattern/Method/Template), or remain UNCERTAIN.

## Experimental Principle

The question is not whether a design sounds reasonable. It is whether it creates observable improvement over frozen LifeOS v0.1.1 without unreasonable Process Cost.

Prefer isolated comparisons:

```text
A = Frozen LifeOS v0.1.1
B = v0.1.1 + one isolated candidate
```

Do not initially combine all candidates, because attribution would be lost.

## Metrics

Retain Clarity, Context Fit, Insight, Decision Support, Actionability, Autonomy and Process Cost. Add Strategy Fit, Calibration Quality, Transfer Value, Assistance Appropriateness and Overhead Penalty.

## C1 — Learning Strategy Router

Test: 30-minute AI Agent orientation; one-month Agent architecture-review preparation; theory-heavy ML learner unable to build projects; next-day teaching preparation; exam retention; six-month production backend capability; and open-ended philosophy exploration.

Pass signals: materially different strategies for different goals; improved Strategy Fit; faster movement into practice; verification matched to target depth; no Process Cost regression for Quick cases.

## C2 — Capability Growth + Assistance Ladder

Use longitudinal cases rather than single-turn answers: first career decision with substantial guidance; a later similar decision where the user already uses criteria/unknowns; a third case where the user provides a complete analysis and asks only for blind-spot review; a new high-risk domain where assistance should temporarily increase; and a transfer case where a prior responsibility-authority lesson is independently reused.

Pass signals: assistance falls appropriately with evidence, can rise for new/high-risk contexts, Autonomy improves without outcome-quality loss, Assistance Level is not treated as a personality label, and real transfer is recognized.

## C3 — Cognitive Augmentation

Test: permanent self-attribution after project failure; sunk-cost continuation; two good uncertain job options; team scaling that reduces delivery; attributing leader disagreement to incompetence; a high-confidence consequential commitment; a trivial reversible lunch choice; and a repeated case after the user has learned Fact/Interpretation/Assumption separation.

Pass signals: less fact/inference confusion; better counterevidence and alternative hypotheses; mental models change actual judgment rather than decorate it; simple cases avoid over-analysis; repeated cases show metacognitive transfer and reduced assistance.

## Interaction Tests

Only after isolated candidates pass: combine C1+C3 for learning to perform architecture judgment; C1+C2 for learn→apply→review→transfer across projects; and C2+C3 for repeated important decisions where calibration should become internalized.

## Experimental Order

```text
Phase 1 Candidate Isolation
        v0.1.1 vs v0.1.1+C1
        v0.1.1 vs v0.1.1+C2
        v0.1.1 vs v0.1.1+C3
Phase 2 Failure Analysis
Phase 3 Interaction Tests for retained candidates
Phase 4 Human Real-world Validation
Phase 5 v0.1.2 Decision
```

## Candidate Gate

A candidate should enter v0.1.2 only if it shows repeated incremental value in target scenarios; improves at least one primary target without materially damaging other core metrics; does not reduce Autonomy; has acceptable Process Cost; has no P0; has remediation for new P1 findings; cannot be fully replaced by a simpler existing mechanism; and any Human Capability claim has behavioral evidence rather than only output-quality scores.

## Version Discipline

```text
Frozen v0.1.1
→ Candidate Experiments
→ Evidence
→ KEEP / CHANGE / REMOVE / DOWNGRADE
→ v0.1.2 Candidate Build
→ Regression
→ Blind + Human Validation
```

> **A LifeOS methodology earns its place through evidence, not because it sounds right.**
