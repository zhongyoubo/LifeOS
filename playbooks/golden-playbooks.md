# LifeOS Golden Playbooks

**English** | [简体中文](./golden-playbooks.zh-CN.md)

Golden Playbooks validate whether the LifeOS Runtime can handle representative real-world situations. They are not fixed answers; they are standardized problem-solving paths.

## 1. Facing a Complex Problem With No Clear Starting Point

Use when information is messy, the problem is unclear, or the first step is unknown.

```text
Clarify Problem → Separate Facts / Assumptions / Unknowns → Map Context → Decompose → Identify Highest-Leverage Question → Choose Smallest Useful Next Action → Observe Feedback
```

Activate: Thinking → Execution → Review.

Ask: What is the real problem? If only one subproblem could be solved, which matters most? Is the current bottleneck information, choice, or action?

## 2. Making an Important Decision

Use for career moves, relocation, major commitments, project choices, and similar consequential decisions.

```text
Clarify Goal & Values → Generate Real Options → Define Criteria → Analyze Trade-offs & Risks → Check Reversibility → Decide → Define Revisit Condition
```

Activate: Self + Goal + Thinking + Decision + Emotion & Energy.

Ask: What am I truly optimizing for? What boundaries must not be crossed? Which consequences are reversible? Is not choosing itself a choice?

## 3. Entering a New Role, Job, or Environment

Use for promotions, job changes, new teams, management roles, parenthood, and other role transitions.

```text
Define Role Purpose → Clarify Responsibilities / Authority / Expectations → Map Stakeholders → Identify Strengths & Gaps → Create 30/60/90-day Outcomes → Build Feedback Loop
```

Activate: Role + Context + Learning + Communication + Execution + Review.

Ask: Why does this role exist? What outcomes are others actually expecting? Which old habits may fail in the new role?

## 4. Taking Over an Unfamiliar or Complex Project

Use for project rescue, unknown domains, incomplete information, or complicated ownership structures.

```text
Understand Outcome → Map System / Stakeholders / Constraints → Reconstruct Current State → Identify Risks & Unknowns → Find Critical Path → Align People → Create First Checkpoint
```

Activate: Thinking + Learning + Communication + Execution + Decision.

Ask: What is the real success criterion? What is the most dangerous unknown? Who holds critical information and decision authority?

## 5. Handling an Important Disagreement or Conflict

Use for work conflict, collaboration disagreement, or important relationship conversations.

```text
Regulate State → Separate Fact / Interpretation / Emotion → Clarify Own Need & Boundary → Understand Other Side's Interest → Communicate → Find Agreement / Disagreement → Define Next Step or Boundary
```

Activate: Emotion & Energy + Thinking + Communication + Decision.

Ask: Are we differing on facts, interpretations, goals, interests, or values? What do I truly need the other person to understand? If agreement is impossible, what boundary is needed?

## 6. Learning a Completely New Domain

Use for new technologies, industries, job capabilities, and cross-domain learning.

```text
Define Capability Goal → Build Knowledge Map → Identify Fundamentals → Learn Minimum Theory → Practice on Real Problem → Get Feedback → Explain / Teach → Transfer
```

Activate: Learning + Thinking + Execution + Review.

Ask: Do I need to know or to perform? What are the fundamental models? What project will expose my misunderstandings fastest?

## 7. Recovering and Learning After an Important Failure

Use after failed goals, projects, mistakes, or major setbacks.

```text
Stabilize State → Reconstruct Facts → Expected vs Actual → Separate Decision Quality / Execution / Luck → Find Causes → Extract Testable Lessons → Define Changes → Restart with Small Action
```

Activate: Emotion & Energy + Review + Thinking + Learning + Execution.

Ask: What actually happened? What was under my control? Which lessons can change future behavior? What is the smallest recovery action?

## Playbook Rule

```text
Playbook ≠ Answer
Playbook = Context-sensitive execution path through LifeOS
```

When reality does not match a playbook's assumptions, return to the Operating Protocol instead of forcing the situation into a template.
